## Overview

1. The production website keeps a sibling checkout of this repo. By default the Next.js app
   reads `../wiki`, or whatever path `POKEBEDROCK_WIKI_PATH` points at, to load Markdown/MDX
   plus localized JSON datasets at request time.
2. Rendering happens inside the website process: `getWikiDoc`, `getWikiNav`, and the
   content helpers read from disk, compile MDX, and cache the result via React's
   `cache()` memoization so repeated requests stay fast. There is no GitHub webhook or
   `WIKI_WEBHOOK_SECRET` anymore—the deployed git revision controls what visitors see.
3. `.github/workflows/search-index.yml` (`wiki-search`) runs on every `main` push and at 06:00 UTC
   daily. It builds the search payloads plus frontend manifests via `npm run build:search`.
4. When `WIKI_SEARCH_SYNC_URL` and `WIKI_SEARCH_SYNC_TOKEN` are configured, the workflow `POST`s
   `build/search-indices.json` to the website backend (`POST /internal/wiki/search-index`). The
   backend validates the bearer token and replaces the Meilisearch indices `wiki-docs`,
   `wiki-pokemon`, and `wiki-moves` from inside the cluster. When the secrets are missing, the run
   still uploads all generated artifacts for manual download/debugging.

## Runtime checkout expectations

| Variable | Description |
| --- | --- |
| `POKEBEDROCK_WIKI_PATH` | Optional absolute path to the wiki repository root. Defaults to `../wiki` relative to the website runtime. |
| `WIKI_EDIT_BASE_URL` | Optional override for the “Edit on GitHub” links rendered by the frontend. Defaults to `https://github.com/pokebedrock/wiki/blob/main`. |

Make sure the deployment artifact contains a current checkout of this repository at the expected
path (for example, mount the repo inside the same container image or provide it via a read-only
volume). Without the checkout the website cannot load docs, localized navigation files, or
`assets/content/**` JSON used by the Pokémon/move pages.

## Search sync contract

| Secret | Description |
| --- | --- |
| `WIKI_SEARCH_SYNC_URL` | HTTPS endpoint that ultimately proxies to the website backend route `/internal/wiki/search-index`. |
| `WIKI_SEARCH_SYNC_TOKEN` | Bearer token validated by the backend before ingesting a payload. |

Payload shape (generated by `scripts/build-search-index.ts`):

```json
{
  "docs": [
    { "id": "en/guides/getting-started", "title": "Getting Started", "body": "…" }
  ],
  "pokemon": [
    { "id": "content/en/pokemon/pikachu", "title": "Pikachu", "body": "…" }
  ],
  "moves": [
    { "id": "content/en/moves/thunderbolt", "title": "Thunderbolt", "body": "…" }
  ]
}
```

### Manual sync test

```bash
export WIKI_SEARCH_SYNC_URL="https://backend.pokebedrock.com/internal/wiki/search-index"
export WIKI_SEARCH_SYNC_TOKEN="<token>"

npm run build:search

curl --fail-with-body --show-error --silent \
  -X POST \
  -H "Authorization: Bearer ${WIKI_SEARCH_SYNC_TOKEN}" \
  -H "Content-Type: application/json" \
  --data-binary @build/search-indices.json \
  "${WIKI_SEARCH_SYNC_URL}"
```

The backend replies with the index UIDs that were updated. On failure it returns a JSON error body
along with the HTTP status code—GitHub Actions surfaces the same response in the job logs.

## Artifacts and cache behavior

- `build/search-index.json` – merged fallback search dataset consumed by the backend for local
  reads or failure scenarios.
- `build/search-indices.json` – multi-index payload uploaded to Meilisearch when sync credentials
  are present.
- `build/content/<locale>/pokemon-manifest.json` – reference data for the Pokémon list and detail
  views inside the website frontend.
- `build/content/<locale>/moves-manifest.json` – move list pagination + metadata.
- `build/content/<locale>/move-learners-manifest.json` – move detail learner tables.

The website frontend caches compiled MDX and manifest JSON via React's `cache()` helper. Redeploy
the website (or restart the container) after updating this repository so the runtime reloads the
latest files from disk. Search index changes do not require a redeploy because the backend writes
directly to Meilisearch.

## Troubleshooting

- **Docs not updating** – confirm the deployed environment actually contains the new wiki commit at
  `POKEBEDROCK_WIKI_PATH` (or `../wiki` by default). Redeploying without syncing this repo leaves
  the website serving an older revision.
- **Search lagging** – check the latest `wiki-search` workflow run. If `WIKI_SEARCH_SYNC_*` secrets
  are unset, the logs will mention that the sync step was skipped.
- **Backend rejects payloads** – verify that the bearer token matches the configured backend secret
  and that the endpoint URL includes `/internal/wiki/search-index`.
